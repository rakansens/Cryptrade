## ドキュメント更新ガイドライン

### 1. ファイル命名規則
- ケバブケース（kebab-case）を使用: `example-document.md`
- 明確で説明的な名前を使用
- バージョン番号は含めない（Gitで管理）

### 2. ドキュメント構造
- 各ドキュメントにはタイトル（H1）を含める
- 目次を含める（長いドキュメントの場合）
- セクションは論理的に構成する
- コード例を積極的に含める

### 3. 更新プロセス
1. 新しいドキュメントは適切なサブディレクトリに配置
2. 既存ドキュメントの大幅な変更時は、古いバージョンをarchiveに移動
3. このREADME.mdの主要ドキュメントセクションを更新
4. 変更内容をコミットメッセージに明記

### 4. マークダウンスタイル
- 見出しは階層的に使用（H1 → H2 → H3）
- コードブロックには言語を指定
- リンクは相対パスを使用
- 画像はassets/imagesディレクトリに保存

### 5. レビュープロセス
- 技術的な正確性の確認
- 文法とスペルチェック
- リンクの有効性確認
- フォーマットの一貫性

## メンテナンス

定期的に以下を実施：
- 古いドキュメントのアーカイブ
- リンク切れの確認と修正
- 内容の最新性確認
